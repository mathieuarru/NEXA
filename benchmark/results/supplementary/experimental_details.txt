NEXA: experimental details for the Supplementary (generated by benchmark/export_supplementary.py)
====================================================================================================

1. COMPONENT ABLATION: what each variant switches off, and what it leaves unchanged
   Reference ('full'): NEXA Direct as published. One-shot Cypher generation first; only if its result
   is empty, staged regeneration (label selection, relationship selection, Cypher generation) followed
   by the correction loop: a Neo4j error -> dedicated syntax repair (<= 3 rounds); an empty result ->
   the query's literals are matched against the values stored in the graph, the LLM picks among the
   top candidates or proposes a synonym, then rewrites the query (<= 3 rounds); still empty -> accepted
   as factual absence. Graph-generated few-shot examples (examples_mode = llm) in every Direct prompt.

   No few-shot examples  [arm 'no-examples'; group: Few-shot examples]
     switched off : Every Direct prompt is zero-shot: the few-shot block of the label-selection, relationship-selection, Cypher-generation and query-correction prompts is empty (NEXA_ABLATE_FEWSHOT_EXAMPLES).
     unchanged    : Everything else, including the identifying-property table given to the generation and correction prompts, the one-shot-then-fallback strategy and the whole correction loop.
     run settings : generation_mode=one_shot_fallback, examples_mode=llm, flags=NEXA_ABLATE_FEWSHOT_EXAMPLES

   Generic examples  [arm 'generic-examples'; group: Few-shot examples]
     switched off : The graph-generated examples are replaced by the generic examples of nexa/models/prompts.py: the same query shapes (single hop, chain, union, intersection, list filter) written with <LABEL>/<REL_TYPE> placeholders, nothing taken from the graph (examples_mode = hardcoded).
     unchanged    : Number and position of the example blocks, every other prompt and component.
     run settings : generation_mode=one_shot_fallback, examples_mode=hardcoded, flags=none

   No recovery  [arm 'bare'; group: Recovery path]
     switched off : The whole recovery path: one one-shot query, executed once, its result final. No staged fallback, no empty-result correction (value matching, LLM selection, rewrite), no repair of Neo4j errors (generation_mode = one_shot, NEXA_ABLATE_EMPTY_RESULT_LOOP, NEXA_ABLATE_SYNTAX_CORRECTION).
     unchanged    : The one-shot generation prompt with its examples and identifying properties, answer synthesis.
     run settings : generation_mode=one_shot, examples_mode=llm, flags=NEXA_ABLATE_EMPTY_RESULT_LOOP NEXA_ABLATE_SYNTAX_CORRECTION

   No empty-result correction  [arm 'no-empty-loop'; group: Recovery path]
     switched off : The empty-result correction loop: an empty result after the staged fallback is accepted as final, without extracting the query's literals, matching them against the database, selecting a candidate or rewriting the query (NEXA_ABLATE_EMPTY_RESULT_LOOP).
     unchanged    : One-shot first, the staged fallback when the one-shot query returns nothing, and the repair of Neo4j errors.
     run settings : generation_mode=one_shot_fallback, examples_mode=llm, flags=NEXA_ABLATE_EMPTY_RESULT_LOOP

   No decomposed fallback  [arm 'one-shot'; group: Recovery path]
     switched off : The staged (decomposed) fallback: when the one-shot query returns nothing, the correction loop repairs that query instead of regenerating it through label selection, relationship selection and staged Cypher generation (generation_mode = one_shot).
     unchanged    : The whole correction loop (value matching, LLM selection, rewrite, error repair).
     run settings : generation_mode=one_shot, examples_mode=llm, flags=none

   No database value matching  [arm 'no-db-matching'; group: Recovery path]
     switched off : Database value matching inside the correction loop: the loop still runs and the LLM still rewrites the query, but without candidate values retrieved from the graph for the query's literals (NEXA_ABLATE_DB_MATCHING).
     unchanged    : One-shot first, staged fallback, the rewrite step and error repair.
     run settings : generation_mode=one_shot_fallback, examples_mode=llm, flags=NEXA_ABLATE_DB_MATCHING

   No LLM candidate selection  [arm 'no-llm-selection'; group: Recovery path]
     switched off : LLM contextual selection: candidate values are still retrieved from the graph, but the top-ranked one is used as is; no LLM choice among the candidates and no LLM-proposed synonym (NEXA_ABLATE_LLM_SELECTION).
     unchanged    : One-shot first, staged fallback, database matching, the rewrite and error repair.
     run settings : generation_mode=one_shot_fallback, examples_mode=llm, flags=NEXA_ABLATE_LLM_SELECTION

   No syntactic correction  [arm 'no-syntax'; group: Recovery path]
     switched off : Syntactic correction: Neo4j errors and notifications are not sent to the dedicated repair prompt; a failing query is handled like an empty one (NEXA_ABLATE_SYNTAX_CORRECTION).
     unchanged    : One-shot first, staged fallback and the empty-result correction loop.
     run settings : generation_mode=one_shot_fallback, examples_mode=llm, flags=NEXA_ABLATE_SYNTAX_CORRECTION

   Fully decomposed strategy  [arm 'decomposed'; group: Generation strategy]
     switched off : The one-shot-first strategy: every question takes the staged path (label selection, relationship selection, Cypher generation) from the start, then the correction loop (generation_mode = decomposed).
     unchanged    : Every prompt and the whole correction loop.
     run settings : generation_mode=decomposed, examples_mode=llm, flags=none

   Every component except the examples and the generation strategy acts only on questions whose
   one-shot query returned no rows or failed ('triggered' questions); on the others every arm follows
   the same path.

2. SAMPLES
   AlzKB, the six ESCARGOT sets, 1 000 stratified questions: n = 1000 of 2975, seed 20260926, strata: set x answer class (True/False: gold x negated statement; MCQ: correct option; open-ended: answer-set size), proportional allocation over all sets (largest remainder).
     per subset: TF 1-hop 188/560; TF 2-hop 182/540; MCQ 1-hop 167/498; MCQ 2-hop 141/419; OE 1-hop 171/508; OE 2-hop 151/450
     representativeness check: the full-set score of 56 of 57 complete configurations falls inside the 95% interval of the same configuration on the sample.
   BioHopR 2-hop, 1 000 stratified questions: n = 1000 of 7633, seed 20260926, strata: meta.path x meta.size_bucket, proportional allocation (largest remainder).
     representativeness check: the full-set score of 7 of 7 complete configurations falls inside the 95% interval of the same configuration on the sample.
   Allocation: proportional to stratum size, largest remainder; within a stratum, a permutation drawn by a
   generator seeded from (seed, stratum), so adding or resizing a stratum does not change the others.

3. ENTITY-NAME PERTURBATIONS
   AlzKB 1-hop questions with a perturbed anchor entity name
     eligibility : 1-hop open-ended and MCQ questions whose anchor ('the <type> <name>') is the exact identifying value of a node in AlzKB (839 eligible; not eligible: {'no anchor phrase': 167})
     base sample : 150 questions, seed 20260926, strata: source set x anchor type, proportional allocation over eligible questions
     case    : lower-cased (title-cased if already lower case)
     typo    : one internal letter deleted (names of 5+ characters)
     alias   : gene symbol replaced by the gene's full name (Gene.commonName)
     dropped     : {'typo: collides with an existing name': 3} (a case or typo variant that is itself the exact name of another node would change the question, and so its gold)
     items       : {'original': 150, 'case': 150, 'typo': 122, 'alias': 71} (gold answers unchanged)
   BioHopR 2-hop questions with a perturbed start entity name
     eligibility : BioHopR 2-hop questions whose start entity, which ends the question, is the exact name of a node of its type in PrimeKG (7498 eligible; not eligible: {'start entity not at the end of the question': 135})
     base sample : 150 questions, seed 20260926, strata: relation path (which fixes the start type), proportional allocation over eligible questions; start types {'drug': 71, 'gene/protein': 21, 'disease': 43, 'effect/phenotype': 15}
     case    : lower-cased (title-cased if already lower case)
     typo    : one internal letter deleted (names of 5+ characters)
     alias   : gene symbol replaced by the gene's NCBI full name, taken from AlzKB (Gene.xrefNcbiGene = PrimeKG GeneProtein.id); PrimeKG itself stores no full name
     dropped     : none (a case or typo variant that is itself the exact name of another node would change the question, and so its gold)
     items       : {'original': 150, 'case': 150, 'typo': 144, 'alias': 21} (gold answers unchanged)
   Why fewer than 150: the typo needs a name of 5+ characters (and no collision); the full name exists
   only for genes (AlzKB: Gene.commonName; BioHopR: NCBI full name through AlzKB, a single match required).
   Arms: complete NEXA Direct and three value-correction ablations (no-empty-loop, no-db-matching,
   no-llm-selection), GPT-4o-mini. Metrics: 'score' = AlzKB pooled primary metric (MCQ accuracy, open-ended
   Jaccard), BioHopR Jaccard; 'exact' = exact answer (MCQ option, exact set match).

4. METRICS AND AGGREGATION
   Primary metric per question: accuracy (0/1) for True/False and MCQ; Jaccard index between the predicted
   and gold entity sets for open-ended questions and BioHopR. Entity matching: NFKC, curly quotes and
   dashes folded, invisible characters removed, whitespace collapsed, trailing period removed, casefold.
   AlzKB pooled primary metric (ablation figure): each of the 1,000 sampled questions keeps the primary
   metric of its subset; the pooled score is their unweighted mean over all questions (subsets therefore
   weigh by their sample size), and the difference is tested with the paired bootstrap below.

5. STATISTICAL TESTS
   Binary outcomes (accuracy): exact two-sided McNemar test on the discordant questions (binomial test of
   min(b, c) of b + c at p = 0.5, scipy.stats); 95% interval of the paired difference by Newcombe's
   method 10 (Wilson intervals combined with the observed phi correlation).
   Graded outcomes (Jaccard, pooled metric): 95% BCa bootstrap interval of the mean paired difference,
   resampling questions with their pair of answers (100,000 resamples; acceleration from the jackknife);
   two-sided sign-flip permutation test on the per-question differences (100,000 sign assignments);
   a p at the resolution limit is reported as p < 1e-05. Generator: numpy default_rng, seed
   20260921 for every comparison (bootstrap then sign flips from the same stream).
   Holm step-down adjustment within each family; significant = Holm-adjusted p < 0.05; intervals are
   not adjusted.
